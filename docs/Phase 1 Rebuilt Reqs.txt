5. **Maintenance planning** through CapEx tracking

6. **Debt visibility** through enhanced financing dashboards

7. **Exit planning** through liquidation scenarios

 

**Timeline Context:** ~4 years before first purchase. Build comprehensively for confident decision-making.

**Config Validation:**

- Existing v2.3 configs must run without modification

- New features opt-in via explicit config flags (e.g., `"seasonality_enabled": true`)

- Validation framework (ob_str_engine/validation/checks.py) must warn on missing new fields but not error

## 1.1 Seasonality Engine & Market Profiles

 

**Goal:** Model market-specific seasonal revenue patterns accurately, replacing flat 78% occupancy assumption with realistic monthly curves.

 

**Complexity:** Large (L) - 8-12 days

**Dependencies:** None

**Priority:** P0 (Highest - foundation for revenue accuracy)

 

### Functional Requirements

 

#### FR-1.1.1: Market Profile System

**User Story:** As a portfolio planner, I need to define market-specific operating parameters so that multi-market portfolios can be accurately modeled.

 

**System shall:**

- Support multiple named market profiles (e.g., "orange_beach", "lake_generic", "custom_market_1")

- Each market profile SHALL define:

  - Base ADR and occupancy assumptions

  - Monthly seasonality multipliers (12 values for ADR, 12 for occupancy)

  - Market-specific expense patterns (insurance rates, property tax rates)

  - Appreciation and inflation rates (overrides to global if specified)

  - Human-readable display name and description

- Provide a default "orange_beach" profile pre-configured with Jorge's assumptions

- Provide a fallback "generic" profile (flat seasonality, national averages)

 

#### FR-1.1.2: Seasonal Revenue Calculation

**User Story:** As a simulation user, I need monthly revenue to reflect seasonal patterns so that cash flow projections are realistic.

 

**System shall:**

- Apply monthly multipliers to base ADR and occupancy for each unit

- Calculate gross monthly revenue as: `ADR × ADR_multiplier × Occupancy × Occ_multiplier × Days × Units`

- Handle partial months correctly (e.g., property purchased mid-month)

- When property purchased mid-year, apply seasonality from the purchase month forward (Option A from questions)

- Aggregate portfolio-level revenue across units in different markets

 

#### FR-1.1.3: Parity Pricing Integration

**User Story:** As an acquisition planner, I need parity price to use seasonal revenue averages so that properties are priced for consistent yield.

 

**System shall:**

- Calculate annual average revenue using seasonal multipliers: `sum(monthly_revenues) / 12`

- Use seasonal average (not flat baseline) in parity price formula in `acquisition.py:calculate_parity_price()`

- Maintain 6.5% unlevered yield target using seasonal NOI

- Document the seasonal adjustment in output columns

 

#### FR-1.1.4: Unit-to-Market Assignment

**User Story:** As a portfolio manager, I need to assign each property to a market profile so that multi-market portfolios are supported.

 

**System shall:**

- Each unit assigned to exactly one market profile by name (string reference)

- Assignment happens at acquisition time (stored in Unit dataclass)

- Support portfolio-wide default market (applies to all units unless overridden)

- Validate that referenced market profile exists in config

 

#### FR-1.1.5: Seasonality Toggle

**User Story:** As an analyst, I need to compare seasonal vs flat projections so that I can quantify the impact of seasonality.

 

**System shall:**

- Provide `"seasonality_enabled": true/false` flag per market profile

- When false, multipliers default to 1.0 (flat revenue, v2.3 behavior)

- Allow scenario comparison: same config with seasonality on vs off

- Log warning if seasonality disabled in a market with defined curves

**Derivation of Orange Beach Multipliers:**

 

Based on provided assumptions:

- Peak (Jun-Aug): Occupancy 90%, ADR +35%

- Shoulder (Mar-May, Sep-Oct): Occupancy 70%, ADR +10%

- Off-season (Nov-Feb): Occupancy 45%, ADR -15%

 

**ADR Multipliers** (baseline $425):

- Off-season: -15% → 0.85

- Shoulder: +10% → 1.10

- Peak: +35% → 1.35

 

**Occupancy Multipliers** (baseline 78%):

- Off-season: 45% / 78% = 0.58

- Shoulder: 70% / 78% = 0.90

- Peak: 90% / 78% = 1.15

 

**Verification:** Annual average should remain ~78%:

```

(0.58×4 + 0.90×5 + 1.15×3) / 12 = (2.32 + 4.50 + 3.45) / 12 = 10.27 / 12 ≈ 0.856

Actual occupancy: 78% × 0.856 ≈ 67% (lower than flat 78% - more realistic!)

```

 

**Important:** The provided assumptions yield an annual average occupancy of ~67%, not 78%. This is expected and more realistic. The baseline 78% should be interpreted as "peak season equivalent" not "annual average." Recommend updating `occupancyBaseline` in config to reflect true annual average once seasonality enabled.

### Calculation Logic & Formulas

 

#### Monthly Revenue Calculation (Replaces Current Logic)

 

**Current code location:** `ob_str_engine/engine/revenue.py:calculate_gross_revenue()`

 

**Current logic (v2.3):**

```python

def calculate_gross_revenue(year, units_owned, config):

    base_adr = config["constants"]["operations"]["adrBaseline2BR"]

    occupancy = config["constants"]["operations"]["occupancyBaseline"]

    inflation = config["market"]["revenueInflationRate"]

 

    adr_this_year = base_adr * (1 + inflation) ** (year - 1)

    gross_monthly = adr_this_year * occupancy * 30 * units_owned  # Flat

    return gross_monthly

```

 

**New logic (v2.4 with seasonality):**

```python

def calculate_gross_revenue_seasonal(year, month, units, config):

    """

    Calculate gross revenue with seasonal adjustments per unit.

 

    Args:

        year: Simulation year (1-30)

        month: Simulation month (1-360)

        units: List[Unit] - all units owned this month

        config: Configuration dict with market_profiles

 

    Returns:

        tuple: (gross_revenue, revenue_details_dict)

    """

    total_revenue = 0.0

    details = {

        "by_market": {},

        "seasonal_adjustment": 0.0,  # vs flat baseline

        "units_breakdown": []

    }

 

    calendar_month = ((month - 1) % 12) + 1  # 1-12 for Jan-Dec

    days_in_month = get_days_in_month(calendar_month)

 

    for unit in units:

        # Get market profile for this unit

        market_name = unit.market_profile

        market = config["market_profiles"].get(market_name)

 

        if not market:

            raise ValueError(f"Unit {unit.unit_id} references unknown market: {market_name}")

 

        # Base rates

        base_adr = market["baseline"]["adr"]

        base_occupancy = market["baseline"]["occupancy"]

 

        # Apply revenue inflation (annual)

        inflation_rate = market.get("market", {}).get("revenue_inflation_rate",

                                                       config["market"]["revenueInflationRate"])

        adr_inflated = base_adr * (1 + inflation_rate) ** (year - 1)

 

        # Apply seasonal multipliers if enabled

        if market.get("seasonality_enabled", False):

            adr_mult = market["seasonality"]["adr_multipliers"][calendar_month - 1]

            occ_mult = market["seasonality"]["occupancy_multipliers"][calendar_month - 1]

        else:

            adr_mult = 1.0

            occ_mult = 1.0

 

        # Effective rates

        adr_effective = adr_inflated * adr_mult

        occupancy_effective = base_occupancy * occ_mult

 

        # Calculate revenue for this unit

        unit_revenue = adr_effective * occupancy_effective * days_in_month

        total_revenue += unit_revenue

 

        # Track details

        flat_revenue = adr_inflated * base_occupancy * days_in_month

        seasonal_delta = unit_revenue - flat_revenue

 

        details["units_breakdown"].append({

            "unit_id": unit.unit_id,

            "market": market_name,

            "adr_base": base_adr,

            "adr_inflated": adr_inflated,

            "adr_multiplier": adr_mult,

            "adr_effective": adr_effective,

            "occupancy_base": base_occupancy,

            "occupancy_multiplier": occ_mult,

            "occupancy_effective": occupancy_effective,

            "revenue": unit_revenue,

            "seasonal_delta": seasonal_delta

        })

 

        # Aggregate by market

        if market_name not in details["by_market"]:

            details["by_market"][market_name] = {

                "units": 0,

                "revenue": 0.0,

                "seasonal_delta": 0.0

            }

        details["by_market"][market_name]["units"] += 1

        details["by_market"][market_name]["revenue"] += unit_revenue

        details["by_market"][market_name]["seasonal_delta"] += seasonal_delta

 

    # Total seasonal adjustment

    details["seasonal_adjustment"] = sum(u["seasonal_delta"] for u in details["units_breakdown"])

 

    return total_revenue, details

```

#### Parity Price Calculation (Updated for Seasonality)

 

**Current code location:** `ob_str_engine/engine/acquisition.py:calculate_parity_price()`

 

**Current logic (v2.3):**

```python

def calculate_parity_price(year, config):

    """Calculate price for 6.5% unlevered yield using flat revenue."""

    base_adr = config["constants"]["operations"]["adrBaseline2BR"]

    occupancy = config["constants"]["operations"]["occupancyBaseline"]

 

    # Annual inflation

    inflation = config["market"]["revenueInflationRate"]

    adr_this_year = base_adr * (1 + inflation) ** (year - 1)

 

    # Annual gross revenue (flat)

    gross_annual = adr_this_year * occupancy * 365

 

    # NOI calculation

    mgmt_pct = config["constants"]["operations"]["mgmtPct"]

    capex_pct = config["constants"]["operations"]["capexPct"]

    hoa_inflation = config["constants"]["operations"]["hoaInflationRate"]

    hoa_base = config["constants"]["operations"]["hoaAnnual"]

    hoa_this_year = hoa_base * (1 + hoa_inflation) ** (year - 1)

 

    noi = gross_annual * (1 - mgmt_pct - capex_pct) - hoa_this_year

 

    # Parity price for 6.5% yield

    target_yield = config["constants"]["acquisition"]["targetYieldUnlevered"]

    insurance_rate = config["constants"]["operations"]["insuranceRate"]

    tax_rate = config["constants"]["operations"]["propertyTaxRate"]

 

    price = noi / (target_yield + insurance_rate + tax_rate)

    return price

```

 

**Updated logic (v2.4 with seasonality):**

```python

def calculate_parity_price(year, config, market_profile_name="orange_beach"):

    """

    Calculate price for 6.5% unlevered yield using seasonal average revenue.

 

    Args:

        year: Acquisition year (1-30)

        config: Configuration dict

        market_profile_name: Market to price for (default: portfolio default)

 

    Returns:

        float: Parity price for this market in this year

    """

    # Get market profile

    if market_profile_name is None:

        market_profile_name = config["policies"]["portfolio"].get("default_market", "orange_beach")

 

    market = config["market_profiles"].get(market_profile_name)

    if not market:

        raise ValueError(f"Unknown market profile: {market_profile_name}")

 

    # Base rates

    base_adr = market["baseline"]["adr"]

    base_occupancy = market["baseline"]["occupancy"]

 

    # Apply annual inflation

    inflation = market.get("market", {}).get("revenue_inflation_rate",

                                              config["market"]["revenueInflationRate"])

    adr_this_year = base_adr * (1 + inflation) ** (year - 1)

 

    # Calculate SEASONAL AVERAGE annual revenue

    if market.get("seasonality_enabled", False):

        monthly_revenues = []

        adr_mults = market["seasonality"]["adr_multipliers"]

        occ_mults = market["seasonality"]["occupancy_multipliers"]

 

        for month_idx in range(12):

            adr_effective = adr_this_year * adr_mults[month_idx]

            occ_effective = base_occupancy * occ_mults[month_idx]

            days = [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31][month_idx]  # Ignore leap years for simplicity

            monthly_revenue = adr_effective * occ_effective * days

            monthly_revenues.append(monthly_revenue)

 

        gross_annual = sum(monthly_revenues)

    else:

        # Flat calculation (v2.3 behavior)

        gross_annual = adr_this_year * base_occupancy * 365

 

    # NOI calculation (same as v2.3)

    mgmt_pct = config["constants"]["operations"]["mgmtPct"]

    capex_pct = config["constants"]["operations"]["capexPct"]

    hoa_inflation = config["constants"]["operations"]["hoaInflationRate"]

    hoa_base = market["expenses"].get("hoa_annual",

                                       config["constants"]["operations"]["hoaAnnual"])

    hoa_this_year = hoa_base * (1 + hoa_inflation) ** (year - 1)

 

    noi = gross_annual * (1 - mgmt_pct - capex_pct) - hoa_this_year

 

    # Parity price for 6.5% yield

    target_yield = config["constants"]["acquisition"]["targetYieldUnlevered"]

    insurance_rate = market["expenses"].get("insurance_rate",

                                             config["constants"]["operations"]["insuranceRate"])

    tax_rate = market["expenses"].get("property_tax_rate",

                                       config["constants"]["operations"]["propertyTaxRate"])

 

    price = noi / (target_yield + insurance_rate + tax_rate)

 

    return price

```

 

**Impact Analysis:**

- File: `ob_str_engine/engine/acquisition.py` (lines 50-80)

  - Seasonal annual revenue: ~$108,000 (estimated, will vary)

## 1.2 Insurance Modeling (Coastal-Specific)

 

**Goal:** Accurately model coastal insurance costs and claim dynamics, replacing flat 3.3% assumption with market-specific rates, named storm deductibles, and claim scenarios.

 

**Complexity:** Medium (M) - 5-7 days

**Dependencies:** 1.1 (market profiles for base rates), 1.3 (events for hurricane claims)

**Priority:** P0 (Highest - critical expense accuracy)

 

### Functional Requirements

 

#### FR-1.2.1: Market-Specific Insurance Rates

**User Story:** As a portfolio planner, I need different insurance rates per market so that coastal vs inland properties are priced correctly.

 

**System shall:**

- Store base insurance rate in market profile (already in 1.1 schema: `"insurance_rate": 0.04`)

- Apply market-specific rate to each unit based on its assigned market

- Support annual insurance inflation per market (default: 7% for coastal, 3% for inland)

- Override global insurance rate when market profile specifies one

 

#### FR-1.2.2: Named Storm Deductibles

**User Story:** As a risk planner, I need to model hurricane deductibles so that I understand out-of-pocket exposure during catastrophic events.

 

**System shall:**

- Define named storm deductible as percentage of property value (e.g., 2%)

- Calculate deductible at time of claim (based on current property value, not purchase price)

- Apply deductible BEFORE insurance payout (owner pays deductible out of reserves)

- Track cumulative deductibles paid over simulation (output metric)

 

#### FR-1.2.3: Flood Insurance (Optional Coverage)

**User Story:** As a coastal property owner, I need to model flood insurance costs for properties in flood zones.

 

**System shall:**

- Support per-unit flood zone flag (`in_flood_zone: true/false`)

- If in flood zone, add annual flood insurance premium (fixed cost, e.g., $2,500/year)

- Flood premium inflates independently (use general inflation rate or override)

- Flood claims handled separately from named storm (different deductible structure)

 

#### FR-1.2.4: Insurance Claim Dynamics (Event-Driven)

**User Story:** As a scenario planner, I need to model insurance claims so that I understand cash flow during recovery.

 

**System shall:**

- Insurance claims triggered by events (defined in 1.3 Event Modeling)

- Event specifies:

  - Repair cost (gross cost before insurance)

  - Insurance coverage percentage (e.g., 90% of costs covered)

  - Deductible percentage (e.g., 2% named storm)

  - Payout delay in months (e.g., 4-6 months typical for hurricanes)

- Owner pays deductible + uncovered costs immediately (draws from reserves)

- Insurance payout arrives X months later (adds to operating cash)

- Track insurance claim status in output (pending, paid, amount)

 

#### FR-1.2.5: Premium Increases After Claims

**User Story:** As a long-term planner, I need to model insurance rate hikes after claims so that I understand multi-year cost impacts.

 

**System shall:**

- After a claim, increase insurance premium for affected property by X% (e.g., 15-30%)

- Premium increase persists for Y years (e.g., 3-5 years)

- If market-wide event (hurricane affects all units), increase applies to all units in that market

- Track "surcharge" separately from base rate (for visualization/reporting)

```python

def calculate_insurance_premium(year, month, units, config):

    """

    Calculate monthly insurance premium with market-specific rates,

    flood insurance, and surcharges.

 

    Args:

        year: Simulation year (1-30)

        month: Simulation month (1-360)

        units: List[Unit] - all units owned

        config: Configuration dict

 

    Returns:

        dict: {

            "base_premium": float,

            "surcharge": float,

            "flood_premium": float,

            "total_premium": float,

            "by_unit": list of dicts

        }

    """

    total_base = 0.0

    total_surcharge = 0.0

    total_flood = 0.0

    by_unit = []

 

    for unit in units:

        # Get market insurance config

        market = config["market_profiles"].get(unit.market_profile)

        ins_config = market["expenses"].get("insurance", {})

 

        # Base rate with inflation

        base_rate = ins_config.get("base_rate", 0.04)

        inflation_rate = ins_config.get("inflation_rate", 0.07)

        inflated_rate = base_rate * (1 + inflation_rate) ** (year - 1)

 

        # Base premium for this unit

        base_premium_annual = unit.value * inflated_rate

        base_premium_monthly = base_premium_annual / 12.0

        total_base += base_premium_monthly

 

        # Surcharge (if active)

        surcharge_monthly = 0.0

        if unit.insurance_surcharge_until_month > 0 and month <= unit.insurance_surcharge_until_month:

            surcharge_monthly = base_premium_monthly * unit.insurance_surcharge_pct

            total_surcharge += surcharge_monthly

 

        # Flood insurance (if in flood zone)

        flood_monthly = 0.0

        if unit.in_flood_zone:

            flood_base = ins_config.get("flood_zone_premium", 2500.0)

            flood_inflation = ins_config.get("flood_zone_inflation_rate", 0.04)

            flood_annual = flood_base * (1 + flood_inflation) ** (year - 1)

            flood_monthly = flood_annual / 12.0

            total_flood += flood_monthly

 

        # Unit total

        unit_total = base_premium_monthly + surcharge_monthly + flood_monthly

 

        by_unit.append({

            "unit_id": unit.unit_id,

            "base_rate": inflated_rate,

            "base_premium": base_premium_monthly,

            "surcharge_pct": unit.insurance_surcharge_pct if month <= unit.insurance_surcharge_until_month else 0.0,

            "surcharge_premium": surcharge_monthly,

            "flood_premium": flood_monthly,

            "total_premium": unit_total

        })

 

    return {

        "base_premium": total_base,

        "surcharge": total_surcharge,

        "flood_premium": total_flood,

        "total_premium": total_base + total_surcharge + total_flood,

        "by_unit": by_unit

    }

```

#### Insurance Claim Processing (Event-Driven)

 

**Integration point:** `ob_str_engine/engine/events.py` (to be created in 1.3)

 

**Logic:** When event with `insurance_claim` is triggered:

 

```python

def process_insurance_claim(event, units, config, operating_cash, month):

    """

    Process insurance claim from an event.

 

    Returns:

        tuple: (updated_operating_cash, claim_pending, surcharge_updates)

    """

    claim = event["insurance_claim"]

    repair_cost = event["impacts"]["repair_cost"]

 

    # Calculate covered amount

    covered_amount = repair_cost * claim["coverage_pct"]

    deductible_pct = claim["deductible_pct"]

 

    # Determine deductible base (property value or repair cost?)

    # For named storm: deductible is % of property value

    # For other: deductible is % of repair cost

    if event["type"] == "catastrophic":

        # Named storm: deductible = % of current property value

        if event["scope"] == "portfolio":

            deductible_base = sum(u.value for u in units)

        else:

            unit = units[event["unit_id"]]

            deductible_base = unit.value

    else:

        # Other claims: deductible = % of repair cost

        deductible_base = repair_cost

 

    deductible_amount = deductible_base * deductible_pct

 

    # Out-of-pocket cost (paid immediately)

    out_of_pocket = deductible_amount + (repair_cost - covered_amount)

    operating_cash -= out_of_pocket

 

    # Insurance payout (arrives later)

    payout_amount = covered_amount - deductible_amount

    payout_month = month + claim["payout_delay_months"]

 

    claim_pending = {

        "payout_amount": payout_amount,

        "payout_month": payout_month,

        "event_name": event["name"]

    }

 

    # Apply surcharge if applicable

    surcharge_updates = []

    if claim.get("triggers_surcharge", False):

        market = config["market_profiles"][units[0].market_profile]  # Assume same market for simplicity

        surcharge_config = market["expenses"]["insurance"]["claim_surcharge"]

 

        increase_pct = surcharge_config["increase_pct"]

        duration_years = surcharge_config["duration_years"]

        surcharge_until_month = month + (duration_years * 12)

 

        # Apply to all units in portfolio event, or just one unit

        if event["scope"] == "portfolio":

            affected_units = units

        else:

            affected_units = [units[event["unit_id"]]]

 

        for unit in affected_units:

            surcharge_updates.append({

                "unit_id": unit.unit_id,

                "surcharge_pct": increase_pct,

                "surcharge_until_month": surcharge_until_month

            })

 

    return operating_cash, claim_pending, surcharge_updates

```

**Goal:** Model market-specific seasonal revenue patterns accurately, replacing flat 78% occupancy assumption with realistic monthly curves.

### Functional Requirements

 

#### FR-1.1.1: Market Profile System

**User Story:** As a portfolio planner, I need to define market-specific operating parameters so that multi-market portfolios can be accurately modeled.

 

**System shall:**

- Support multiple named market profiles (e.g., "orange_beach", "lake_generic", "custom_market_1")

- Each market profile SHALL define:

  - Base ADR and occupancy assumptions

  - Monthly seasonality multipliers (12 values for ADR, 12 for occupancy)

  - Market-specific expense patterns (insurance rates, property tax rates)

  - Appreciation and inflation rates (overrides to global if specified)

  - Human-readable display name and description

- Provide a default "orange_beach" profile pre-configured with Jorge's assumptions

- Provide a fallback "generic" profile (flat seasonality, national averages)

 

#### FR-1.1.2: Seasonal Revenue Calculation

**User Story:** As a simulation user, I need monthly revenue to reflect seasonal patterns so that cash flow projections are realistic.

 

**System shall:**

- Apply monthly multipliers to base ADR and occupancy for each unit

- Calculate gross monthly revenue as: `ADR × ADR_multiplier × Occupancy × Occ_multiplier × Days × Units`

- Handle partial months correctly (e.g., property purchased mid-month)

- When property purchased mid-year, apply seasonality from the purchase month forward (Option A from questions)

- Aggregate portfolio-level revenue across units in different markets

 

#### FR-1.1.3: Parity Pricing Integration

**User Story:** As an acquisition planner, I need parity price to use seasonal revenue averages so that properties are priced for consistent yield.

 

**System shall:**

- Calculate annual average revenue using seasonal multipliers: `sum(monthly_revenues) / 12`

- Use seasonal average (not flat baseline) in parity price formula in `acquisition.py:calculate_parity_price()`

- Maintain 6.5% unlevered yield target using seasonal NOI

- Document the seasonal adjustment in output columns

 

#### FR-1.1.4: Unit-to-Market Assignment

**User Story:** As a portfolio manager, I need to assign each property to a market profile so that multi-market portfolios are supported.

 

**System shall:**

- Each unit assigned to exactly one market profile by name (string reference)

- Assignment happens at acquisition time (stored in Unit dataclass)

- Support portfolio-wide default market (applies to all units unless overridden)

- Validate that referenced market profile exists in config

 

#### FR-1.1.5: Seasonality Toggle

**User Story:** As an analyst, I need to compare seasonal vs flat projections so that I can quantify the impact of seasonality.

 

**System shall:**

- Provide `"seasonality_enabled": true/false` flag per market profile

- When false, multipliers default to 1.0 (flat revenue, v2.3 behavior)

- Allow scenario comparison: same config with seasonality on vs off

- Log warning if seasonality disabled in a market with defined curves

```python
def calculate_gross_revenue_seasonal(year, month, units, config):

    """

    Calculate gross revenue with seasonal adjustments per unit.

 

    Args:

        year: Simulation year (1-30)

        month: Simulation month (1-360)

        units: List[Unit] - all units owned this month

        config: Configuration dict with market_profiles

 

    Returns:

        tuple: (gross_revenue, revenue_details_dict)

    """

    total_revenue = 0.0

    details = {

        "by_market": {},

        "seasonal_adjustment": 0.0,  # vs flat baseline

        "units_breakdown": []

    }

 

    calendar_month = ((month - 1) % 12) + 1  # 1-12 for Jan-Dec

    days_in_month = get_days_in_month(calendar_month)

 

    for unit in units:

        # Get market profile for this unit

        market_name = unit.market_profile

        market = config["market_profiles"].get(market_name)

 

        if not market:

            raise ValueError(f"Unit {unit.unit_id} references unknown market: {market_name}")

 

        # Base rates

        base_adr = market["baseline"]["adr"]

        base_occupancy = market["baseline"]["occupancy"]

 

        # Apply revenue inflation (annual)

        inflation_rate = market.get("market", {}).get("revenue_inflation_rate",

                                                       config["market"]["revenueInflationRate"])

        adr_inflated = base_adr * (1 + inflation_rate) ** (year - 1)

 

        # Apply seasonal multipliers if enabled

        if market.get("seasonality_enabled", False):

            adr_mult = market["seasonality"]["adr_multipliers"][calendar_month - 1]

            occ_mult = market["seasonality"]["occupancy_multipliers"][calendar_month - 1]

        else:

            adr_mult = 1.0

            occ_mult = 1.0

 

        # Effective rates

        adr_effective = adr_inflated * adr_mult

        occupancy_effective = base_occupancy * occ_mult

 

        # Calculate revenue for this unit

        unit_revenue = adr_effective * occupancy_effective * days_in_month

        total_revenue += unit_revenue

 

        # Track details

        flat_revenue = adr_inflated * base_occupancy * days_in_month

        seasonal_delta = unit_revenue - flat_revenue

 

        details["units_breakdown"].append({

            "unit_id": unit.unit_id,

            "market": market_name,

            "adr_base": base_adr,

            "adr_inflated": adr_inflated,

            "adr_multiplier": adr_mult,

            "adr_effective": adr_effective,

            "occupancy_base": base_occupancy,

            "occupancy_multiplier": occ_mult,

            "occupancy_effective": occupancy_effective,

            "revenue": unit_revenue,

            "seasonal_delta": seasonal_delta

        })

 

        # Aggregate by market

        if market_name not in details["by_market"]:

            details["by_market"][market_name] = {

                "units": 0,

                "revenue": 0.0,

                "seasonal_delta": 0.0

            }

        details["by_market"][market_name]["units"] += 1

        details["by_market"][market_name]["revenue"] += unit_revenue

        details["by_market"][market_name]["seasonal_delta"] += seasonal_delta

 

    # Total seasonal adjustment

    details["seasonal_adjustment"] = sum(u["seasonal_delta"] for u in details["units_breakdown"])

 

    return total_revenue, details

```

```python
def calculate_parity_price(year, config):

    """Calculate price for 6.5% unlevered yield using flat revenue."""

    base_adr = config["constants"]["operations"]["adrBaseline2BR"]

    occupancy = config["constants"]["operations"]["occupancyBaseline"]

 

    # Annual inflation

    inflation = config["market"]["revenueInflationRate"]

    adr_this_year = base_adr * (1 + inflation) ** (year - 1)

 

    # Annual gross revenue (flat)

    gross_annual = adr_this_year * occupancy * 365

 

    # NOI calculation

    mgmt_pct = config["constants"]["operations"]["mgmtPct"]

    capex_pct = config["constants"]["operations"]["capexPct"]

    hoa_inflation = config["constants"]["operations"]["hoaInflationRate"]

    hoa_base = config["constants"]["operations"]["hoaAnnual"]

    hoa_this_year = hoa_base * (1 + hoa_inflation) ** (year - 1)

 

    noi = gross_annual * (1 - mgmt_pct - capex_pct) - hoa_this_year

 

    # Parity price for 6.5% yield

    target_yield = config["constants"]["acquisition"]["targetYieldUnlevered"]

    insurance_rate = config["constants"]["operations"]["insuranceRate"]

    tax_rate = config["constants"]["operations"]["propertyTaxRate"]
```

```python

def calculate_parity_price(year, config, market_profile_name="orange_beach"):

    """

    Calculate price for 6.5% unlevered yield using seasonal average revenue.

 

    Args:

        year: Acquisition year (1-30)

        config: Configuration dict

        market_profile_name: Market to price for (default: portfolio default)

 

    Returns:

        float: Parity price for this market in this year

    """

    # Get market profile

    if market_profile_name is None:

        market_profile_name = config["policies"]["portfolio"].get("default_market", "orange_beach")

 

    market = config["market_profiles"].get(market_profile_name)

    if not market:

        raise ValueError(f"Unknown market profile: {market_profile_name}")

 

    # Base rates

    base_adr = market["baseline"]["adr"]

    base_occupancy = market["baseline"]["occupancy"]

 

    # Apply annual inflation

    inflation = market.get("market", {}).get("revenue_inflation_rate",

                                              config["market"]["revenueInflationRate"])

    adr_this_year = base_adr * (1 + inflation) ** (year - 1)

 

    # Calculate SEASONAL AVERAGE annual revenue

    if market.get("seasonality_enabled", False):

        monthly_revenues = []

        adr_mults = market["seasonality"]["adr_multipliers"]

        occ_mults = market["seasonality"]["occupancy_multipliers"]

 

        for month_idx in range(12):

            adr_effective = adr_this_year * adr_mults[month_idx]

            occ_effective = base_occupancy * occ_mults[month_idx]

            days = [31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31][month_idx]  # Ignore leap years for simplicity

            monthly_revenue = adr_effective * occ_effective * days

            monthly_revenues.append(monthly_revenue)

 

        gross_annual = sum(monthly_revenues)

    else:

        # Flat calculation (v2.3 behavior)

        gross_annual = adr_this_year * base_occupancy * 365

 

    # NOI calculation (same as v2.3)

    mgmt_pct = config["constants"]["operations"]["mgmtPct"]

    capex_pct = config["constants"]["operations"]["capexPct"]

    hoa_inflation = config["constants"]["operations"]["hoaInflationRate"]

    hoa_base = market["expenses"].get("hoa_annual",

                                       config["constants"]["operations"]["hoaAnnual"])

    hoa_this_year = hoa_base * (1 + hoa_inflation) ** (year - 1)

 

    noi = gross_annual * (1 - mgmt_pct - capex_pct) - hoa_this_year

 

    # Parity price for 6.5% yield

    target_yield = config["constants"]["acquisition"]["targetYieldUnlevered"]

    insurance_rate = market["expenses"].get("insurance_rate",

                                             config["constants"]["operations"]["insuranceRate"])

    tax_rate = market["expenses"].get("property_tax_rate",

                                       config["constants"]["operations"]["propertyTaxRate"])

 

    price = noi / (target_yield + insurance_rate + tax_rate)

 

    return price

```

```python
def validate_seasonality_multipliers(config: dict) -> ValidationResult:

    """Verify monthly multipliers are reasonable (0.3-3.0 range)."""

    if "market_profiles" not in config:

        return ValidationResult(

            check_name="seasonality_multipliers",

            status="skip",

            message="No market profiles to validate",

            details={}

        )

 

    issues = []

    for market_name, market in config["market_profiles"].items():

        if not market.get("seasonality_enabled", False):

            continue

 

        seasonality = market.get("seasonality", {})

        adr_mults = seasonality.get("adr_multipliers", [])

        occ_mults = seasonality.get("occupancy_multipliers", [])

 

        # Check length

        if len(adr_mults) != 12:

            issues.append(f"{market_name}: adr_multipliers has {len(adr_mults)} values, need 12")

        if len(occ_mults) != 12:

            issues.append(f"{market_name}: occupancy_multipliers has {len(occ_mults)} values, need 12")

 

        # Check range

        for idx, mult in enumerate(adr_mults):

            if mult < 0.3 or mult > 3.0:

                issues.append(f"{market_name}: adr_multipliers[{idx}] = {mult} (out of range 0.3-3.0)")

 

        for idx, mult in enumerate(occ_mults):

            if mult < 0.3 or mult > 3.0:

                issues.append(f"{market_name}: occupancy_multipliers[{idx}] = {mult} (out of range 0.3-3.0)")

 

    if issues:

        return ValidationResult(

            check_name="seasonality_multipliers",

            status="error",

            message=f"Found {len(issues)} issues with seasonal multipliers",

            details={"issues": issues}

        )

 

    return ValidationResult(

        check_name="seasonality_multipliers",

        status="pass",

        message="All seasonal multipliers in valid range",

        details={}

    )
```

## 1.2 Insurance Modeling (Coastal-Specific)

 

**Goal:** Accurately model coastal insurance costs and claim dynamics, replacing flat 3.3% assumption with market-specific rates, named storm deductibles, and claim scenarios.

 

**Complexity:** Medium (M) - 5-7 days

**Dependencies:** 1.1 (market profiles for base rates), 1.3 (events for hurricane claims)

**Priority:** P0 (Highest - critical expense accuracy)

 

### Functional Requirements

 

#### FR-1.2.1: Market-Specific Insurance Rates

**User Story:** As a portfolio planner, I need different insurance rates per market so that coastal vs inland properties are priced correctly.

 

**System shall:**

- Store base insurance rate in market profile (already in 1.1 schema: `"insurance_rate": 0.04`)

- Apply market-specific rate to each unit based on its assigned market

- Support annual insurance inflation per market (default: 7% for coastal, 3% for inland)

- Override global insurance rate when market profile specifies one

 

#### FR-1.2.2: Named Storm Deductibles

**User Story:** As a risk planner, I need to model hurricane deductibles so that I understand out-of-pocket exposure during catastrophic events.

 

**System shall:**

- Define named storm deductible as percentage of property value (e.g., 2%)

- Calculate deductible at time of claim (based on current property value, not purchase price)

- Apply deductible BEFORE insurance payout (owner pays deductible out of reserves)

- Track cumulative deductibles paid over simulation (output metric)

 

#### FR-1.2.3: Flood Insurance (Optional Coverage)

**User Story:** As a coastal property owner, I need to model flood insurance costs for properties in flood zones.

 

**System shall:**

- Support per-unit flood zone flag (`in_flood_zone: true/false`)

- If in flood zone, add annual flood insurance premium (fixed cost, e.g., $2,500/year)

- Flood premium inflates independently (use general inflation rate or override)

- Flood claims handled separately from named storm (different deductible structure)

 

#### FR-1.2.4: Insurance Claim Dynamics (Event-Driven)

**User Story:** As a scenario planner, I need to model insurance claims so that I understand cash flow during recovery.

 

**System shall:**

- Insurance claims triggered by events (defined in 1.3 Event Modeling)

- Event specifies:

  - Repair cost (gross cost before insurance)

  - Insurance coverage percentage (e.g., 90% of costs covered)

  - Deductible percentage (e.g., 2% named storm)

  - Payout delay in months (e.g., 4-6 months typical for hurricanes)

- Owner pays deductible + uncovered costs immediately (draws from reserves)

- Insurance payout arrives X months later (adds to operating cash)

- Track insurance claim status in output (pending, paid, amount)

 

#### FR-1.2.5: Premium Increases After Claims

**User Story:** As a long-term planner, I need to model insurance rate hikes after claims so that I understand multi-year cost impacts.

 

**System shall:**

- After a claim, increase insurance premium for affected property by X% (e.g., 15-30%)

- Premium increase persists for Y years (e.g., 3-5 years)

- If market-wide event (hurricane affects all units), increase applies to all units in that market

- Track "surcharge" separately from base rate (for visualization/reporting)

```python

def calculate_insurance_premium(year, month, units, config):

    """

    Calculate monthly insurance premium with market-specific rates,

    flood insurance, and surcharges.

 

    Args:

        year: Simulation year (1-30)

        month: Simulation month (1-360)

        units: List[Unit] - all units owned

        config: Configuration dict

 

    Returns:

        dict: {

            "base_premium": float,

            "surcharge": float,

            "flood_premium": float,

            "total_premium": float,

            "by_unit": list of dicts

        }

    """

    total_base = 0.0

    total_surcharge = 0.0

    total_flood = 0.0

    by_unit = []

 

    for unit in units:

        # Get market insurance config

        market = config["market_profiles"].get(unit.market_profile)

        ins_config = market["expenses"].get("insurance", {})

 

        # Base rate with inflation

        base_rate = ins_config.get("base_rate", 0.04)

        inflation_rate = ins_config.get("inflation_rate", 0.07)

        inflated_rate = base_rate * (1 + inflation_rate) ** (year - 1)

 

        # Base premium for this unit

        base_premium_annual = unit.value * inflated_rate

        base_premium_monthly = base_premium_annual / 12.0

        total_base += base_premium_monthly

 

        # Surcharge (if active)

        surcharge_monthly = 0.0

        if unit.insurance_surcharge_until_month > 0 and month <= unit.insurance_surcharge_until_month:

            surcharge_monthly = base_premium_monthly * unit.insurance_surcharge_pct

            total_surcharge += surcharge_monthly

 

        # Flood insurance (if in flood zone)

        flood_monthly = 0.0

        if unit.in_flood_zone:

            flood_base = ins_config.get("flood_zone_premium", 2500.0)

            flood_inflation = ins_config.get("flood_zone_inflation_rate", 0.04)

            flood_annual = flood_base * (1 + flood_inflation) ** (year - 1)

            flood_monthly = flood_annual / 12.0

            total_flood += flood_monthly

 

        # Unit total

        unit_total = base_premium_monthly + surcharge_monthly + flood_monthly

 

        by_unit.append({

            "unit_id": unit.unit_id,

            "base_rate": inflated_rate,

            "base_premium": base_premium_monthly,

            "surcharge_pct": unit.insurance_surcharge_pct if month <= unit.insurance_surcharge_until_month else 0.0,

            "surcharge_premium": surcharge_monthly,

            "flood_premium": flood_monthly,

            "total_premium": unit_total

        })

 

    return {

        "base_premium": total_base,

        "surcharge": total_surcharge,

        "flood_premium": total_flood,

        "total_premium": total_base + total_surcharge + total_flood,

        "by_unit": by_unit

    }

```

#### Insurance Claim Processing (Event-Driven)

 

**Integration point:** `ob_str_engine/engine/events.py` (to be created in 1.3)

 

**Logic:** When event with `insurance_claim` is triggered:

 

```python

def process_insurance_claim(event, units, config, operating_cash, month):

    """

    Process insurance claim from an event.

 

    Returns:

        tuple: (updated_operating_cash, claim_pending, surcharge_updates)

    """

    claim = event["insurance_claim"]

    repair_cost = event["impacts"]["repair_cost"]

 

    # Calculate covered amount

    covered_amount = repair_cost * claim["coverage_pct"]

    deductible_pct = claim["deductible_pct"]

 

    # Determine deductible base (property value or repair cost?)

    # For named storm: deductible is % of property value

    # For other: deductible is % of repair cost

    if event["type"] == "catastrophic":

        # Named storm: deductible = % of current property value

        if event["scope"] == "portfolio":

            deductible_base = sum(u.value for u in units)

        else:

            unit = units[event["unit_id"]]

            deductible_base = unit.value

    else:

        # Other claims: deductible = % of repair cost

        deductible_base = repair_cost

 

    deductible_amount = deductible_base * deductible_pct

 

    # Out-of-pocket cost (paid immediately)

    out_of_pocket = deductible_amount + (repair_cost - covered_amount)

    operating_cash -= out_of_pocket

 

    # Insurance payout (arrives later)

    payout_amount = covered_amount - deductible_amount

    payout_month = month + claim["payout_delay_months"]

 

    claim_pending = {

        "payout_amount": payout_amount,

        "payout_month": payout_month,

        "event_name": event["name"]

    }

 

    # Apply surcharge if applicable

    surcharge_updates = []

    if claim.get("triggers_surcharge", False):

        market = config["market_profiles"][units[0].market_profile]  # Assume same market for simplicity

        surcharge_config = market["expenses"]["insurance"]["claim_surcharge"]

 

        increase_pct = surcharge_config["increase_pct"]

        duration_years = surcharge_config["duration_years"]

        surcharge_until_month = month + (duration_years * 12)

 

        # Apply to all units in portfolio event, or just one unit

        if event["scope"] == "portfolio":

            affected_units = units

        else:

            affected_units = [units[event["unit_id"]]]

 

        for unit in affected_units:

            surcharge_updates.append({

                "unit_id": unit.unit_id,

                "surcharge_pct": increase_pct,

                "surcharge_until_month": surcharge_until_month

            })

 

    return operating_cash, claim_pending, surcharge_updates

```

- Insurance claim logic called from event processor

- Modifies `operating_cash` (immediate deductible payment)

- Creates pending payout (tracked in simulation state)

- Updates `unit.insurance_surcharge_*` fields

### Calculation Logic & Formulas

 

#### System Age Calculation

 

```python

def calculate_system_age(acquisition_year, current_year, initial_age):

    """Calculate current age of a system."""

    years_owned = current_year - acquisition_year

    return initial_age + years_owned

 

# Example:

# Unit acquired Year 3, HVAC was 5 years old at purchase

# Current year: 10

# HVAC age: 5 + (10 - 3) = 12 years old

```

 

#### Replacement Trigger Detection

 

```python

def check_for_replacement_needs(unit, year, config):

    """

    Check if any systems are due for replacement.

 

    Returns:

        list: System names that need replacement

    """

    capex_config = config["constants"]["capex_schedule"]

    lifespans = capex_config["expected_lifespans"]

 

    systems_to_replace = []

 

    for system, lifespan in lifespans.items():

        current_age = calculate_system_age(

            unit.acquisition_year,

            year,

            unit.system_ages.get(system, 0)

        )

 

        if current_age >= lifespan:

            systems_to_replace.append(system)

 

    return systems_to_replace

```

 

#### CapEx Funding Waterfall

 

```python

def fund_capex_expense(cost, capex_reserve, operating_cash):

    """

    Fund CapEx expense using waterfall logic.

 

    Returns:

        tuple: (updated_capex_reserve, updated_operating_cash, funded_amount, shortfall)

    """

    # Step 1: Draw from CapEx reserve

    from_reserve = min(cost, capex_reserve)

    capex_reserve -= from_reserve

    remaining_cost = cost - from_reserve

 

    # Step 2: Draw from operating cash if needed

    from_operating = min(remaining_cost, operating_cash)

    operating_cash -= from_operating

    remaining_cost -= from_operating

 

    funded_amount = from_reserve + from_operating

    shortfall = remaining_cost

 

    if shortfall > 0:

        # Flag warning: Insufficient funds for CapEx

        pass

 

    return capex_reserve, operating_cash, funded_amount, shortfall

```

## 1.7 Exit Strategy Modeling

#### FR-1.7.1: Unit Sale Event

**User Story:** As an exit planner, I need to model selling individual units so that I can plan staggered exits.

 

**System shall:**

- Define unit sale as an event (integrates with 1.3 event system)

- Sale event specifies:

  - Unit ID to sell

  - Sale year and month

  - Sale price (or formula: current market value × multiplier)

  - Selling costs (commission, closing costs)

- Calculate sale proceeds:

  - Gross proceeds = sale price

  - Less: Agent commission (6% default)

  - Less: Closing costs (2% default)

  - Less: Remaining debt payoff

  - Net proceeds = amount to owner

- After sale:

  - Remove unit from portfolio

  - Net proceeds added to operating cash (or distributed)

  - Continue simulation with remaining units

**User Story:** As an investor, I need to model selling the entire portfolio at once so that I can compare to staggered exit.

 

**System shall:**

- Portfolio sale = single event selling all units simultaneously

- Calculate total proceeds:

  - Sum of all unit values (with discount applied)

  - Less: Total selling costs

  - Less: Total remaining debt

  - Net proceeds to owner

- After portfolio sale:

  - Simulation effectively ends (no more units)

  - Final distribution of proceeds

  - IRR calculation to sale date

```python
        dict: Sale breakdown

    """

    sale_details = sale_event["sale_details"]

 

    # Sale price

    multiplier = sale_details.get("sale_price_multiplier", 1.0)

    sale_price = unit.value * multiplier

 

    # Selling costs

    commission_pct = sale_details.get("commission_pct", 0.06)

    closing_pct = sale_details.get("closing_cost_pct", 0.02)

 

    commission = sale_price * commission_pct

    closing_costs = sale_price * closing_pct

    total_costs = commission + closing_costs

 

    # Debt payoff

    debt_payoff = unit.debt

 

    # Net proceeds

    net_proceeds = sale_price - total_costs - debt_payoff

 

    # Tax warning (depreciation recapture)

    cumulative_depreciation = unit.cumulative_depreciation

    capital_gain = sale_price - unit.purchase_price

 

    return {

        "unit_id": unit.unit_id,

        "sale_price": sale_price,

        "commission": commission,

        "closing_costs": closing_costs,

        "debt_payoff": debt_payoff,

        "net_proceeds": net_proceeds,

        "cumulative_depreciation": cumulative_depreciation,

        "capital_gain": capital_gain,

        "tax_warning": f"Estimated recapture: ${cumulative_depreciation:,.0f}. Consult CPA."

    }

```

```python
def process_sale_event(event, units, operating_cash, month, config):

    """

    Process a unit or portfolio sale event.

 

    Returns:

        tuple: (updated_units, updated_operating_cash, sale_proceeds)

    """

    if event["scope"] == "unit":

        # Sell single unit

        unit_id = event["unit_id"]

        unit = units[unit_id]

 

        sale_breakdown = process_unit_sale(unit, event, config)

 

        # Remove unit from portfolio

        units = [u for u in units if u.unit_id != unit_id]

 

        # Add net proceeds to cash (or distribute)

        if event["sale_details"]["proceeds_allocation"] == "distribute":

            # Trigger distribution

            pass

        else:

            operating_cash += sale_breakdown["net_proceeds"]

 

    elif event["scope"] == "portfolio":

        # Sell all units

        total_proceeds = 0

        for unit in units:

            sale_breakdown = process_unit_sale(unit, event, config)

            total_proceeds += sale_breakdown["net_proceeds"]

 

        # Clear portfolio

        units = []

 

        # Distribute proceeds

        operating_cash += total_proceeds

 

    return units, operating_cash, total_proceeds

```
